# Навыки и возможности yandex.direct

`yandex.direct` — это не набор несвязанных промптов, а один оркестратор
`$yandex-direct`, который выбирает нужные режимы по задаче и ведет кампанию через
полный производственный цикл.

```text
brief и экономика
  → спрос и интенты
  → структура ЕПК
  → объявления и посадочная
  → модерация
  → измерение
  → безопасная публикация
  → тесты и оптимизация
```

## 1. Полный запуск кампании

Когда применять: новый продукт, новый регион, пересбор старого аккаунта или запуск
с нуля.

Что делает:

- собирает brief: продукт, география, аудитория, URL, бюджет и ограничения;
- рассчитывает допустимый CPA, break-even CPC, ДРР и сценарии маржинальности;
- проверяет готовность посадочной и измерений;
- последовательно вызывает остальные режимы;
- формирует dry-run пакет или план безопасной публикации.

Что отдает:

- зафиксированные входные данные и допущения;
- семантическое ядро;
- структуру кампаний и групп;
- объявления и API-payload;
- план Метрики, запуска и последующей оптимизации.

Инструкция: [`workflow.md`](../skills/yandex-direct/references/workflow.md).

## 2. Сбор и очистка семантики

Когда применять: подбор ключевых фраз, расширение охвата, поиск упущенного спроса,
проверка сезонности или запуск в новом регионе.

Что умеет:

- работать с актуальным Yandex Search API Wordstat v2;
- получать до 2 000 фраз на один seed-запрос;
- разделять основные результаты и смысловые ассоциации;
- анализировать динамику спроса, регионы, устройства и affinity;
- понимать операторы `-`, `!`, `+`, `""`, `[]`, `()` и `|`;
- объединять регистр, `ё/е`, пунктуационные и другие технические дубли;
- не выдавать модельную оценку за измеренную частотность.

Отдельно маркируются:

- `target` — прямой покупательский спрос;
- `conditional` — подходит только определенному офферу или странице;
- `research` — информационный или ранний спрос;
- `negative` — другой объект покупки;
- `review` — неоднозначный запрос, требующий проверки.

Результат: CSV с фразой, источником, измеренной частотностью, регионом, устройством,
интентом, кластером, посадочной и причиной решения.

Инструкция: [`semantics.md`](../skills/yandex-direct/references/semantics.md).

Команда нормализации:

```bash
python skills/yandex-direct/scripts/yandex_direct_toolkit.py \
  normalize-semantics input.csv \
  --output outputs/semantics.csv \
  --offer-term "теплица" \
  --exclude-term "чертеж"
```

## 3. Проверка покупательского интента и анализ конкурентов

Когда применять: запрос выглядит релевантным по словам, но непонятно, готов ли
пользователь покупать именно ваш продукт.

Что делает:

- проверяет репрезентативные запросы через выдачу Яндекса;
- определяет реальный объект покупки;
- отличает покупателя продукта от покупателя аксессуара, соискателя, ученика,
  владельца, ищущего ремонт, и пользователя, ищущего бесплатный файл;
- фиксирует доминирующие типы результатов: услуги, товары, карты, агрегаторы, статьи;
- собирает реальные рыночные офферы конкурентов;
- находит незакрытые возражения и слабые места предложений;
- формирует собственные углы без копирования чужих объявлений.

Результат: таблица `запрос → интент → конкуренты → рыночный пробел → наш угол →
подходящая посадочная`.

## 4. Архитектура ЕПК

Когда применять: требуется спроектировать или перестроить аккаунт Яндекс Директа.

Что умеет:

- работать с Единой перфоманс-кампанией;
- разделять Search non-brand, Search brand, запросы конкурентов, РСЯ,
  ретаргетинг и товарные сценарии;
- объединять фразы по одному покупательскому заданию, а не по общему слову;
- проектировать группы с одной посадочной и совместимыми объявлениями;
- строить глобальные, кампанийные, групповые и межгрупповые минус-фразы;
- планировать категории автотаргетинга как измеряемый эксперимент;
- выбирать стратегию по качеству конверсионного сигнала;
- не дробить низкий объем на структуры, которые не могут обучаться.

Результат: карта `кампания → место показа → группа → интент → фразы →
автотаргетинг → объявление → посадочная`.

Инструкция:
[`campaign-architecture.md`](../skills/yandex-direct/references/campaign-architecture.md).

## 5. Генерация комбинаторных объявлений

Когда применять: нужны новые объявления, варианты для тестирования или обновление
устаревших текстово-графических объявлений.

Формат адаптирован под текущий Яндекс Директ:

- тип объявления — `ResponsiveAd`;
- 1–7 заголовков, практически рекомендуется 5–7;
- 1–3 текста, практически рекомендуется 3;
- заголовок — до 56 символов;
- текст — до 81 обычного символа и до 15 узких знаков;
- отсутствует устаревший дополнительный заголовок TextAd;
- каждая комбинация заголовка и текста должна читаться самостоятельно.

Навык использует разные рекламные углы:

- точный поисковый запрос;
- результат для клиента;
- подтвержденное отличие;
- цена, срок, доставка или комплектация;
- снятие возражения;
- специализация под аудиторию;
- конкретный следующий шаг.

Перед генерацией создается реестр доказательств. Инструмент не выдумывает цены,
сроки, рейтинги, отзывы, гарантии и превосходство над конкурентами.

Результат: готовый набор элементов с количеством символов, рекламным углом,
источником каждого утверждения и примечанием по модерации.

Инструкция:
[`creative-and-landing.md`](../skills/yandex-direct/references/creative-and-landing.md).

Проверка пакета:

```bash
python skills/yandex-direct/scripts/yandex_direct_toolkit.py \
  validate-package examples/campaign-package.example.json
```

## 6. Message match и посадочные страницы

Когда применять: объявление получает клики, но страница плохо конвертирует, либо
нужно подготовить посадочную перед запуском.

Что проверяет:

- совпадает ли смысл запроса, объявления и первого экрана;
- видны ли цена, срок, скидка, гарантия и комплектация из объявления;
- соответствует ли H1 основному рекламному сообщению;
- находится ли CTA на первом мобильном экране;
- подтверждаются ли заявления фактами;
- нет ли противоречий между заголовками, текстами и страницей;
- корректно ли работают формы и thank-you событие.

Вспомогательная метрика overlap сравнивает значимые слова главного заголовка и H1.
Она помогает найти явный разрыв, но не заменяет смысловую проверку.

Результат: список блокеров страницы и согласованная цепочка
`поисковый запрос → ResponsiveAd → H1 → доказательство → CTA`.

## 7. Проверка модерации и регулируемых тематик

Когда применять: перед каждым live-запуском и обязательно для медицины, финансов,
юридических услуг, недвижимости, образования, БАД, билетов, 18+ и других
чувствительных категорий.

Что проверяет:

- грамотность, CAPS, повторы и агрессивные формулировки;
- недостоверные и сенсационные заявления;
- слова «лучший», «№1», «гарантированно» без независимого доказательства;
- соответствие объявления странице перехода;
- доступность сайта, контакты и юридические реквизиты;
- быстрые ссылки, отображаемый путь, изображения и видео;
- предупреждения, возрастную маркировку и необходимые документы;
- запретные и ограниченные категории.

Результат: `pass`, `fail` или `needs_legal_review` для каждого правила с URL
официального источника и требуемым доказательством.

Инструкция: [`compliance.md`](../skills/yandex-direct/references/compliance.md).

## 8. Метрика, цели и качество конверсий

Когда применять: до запуска, при расхождении данных или перед масштабированием.

Что умеет:

- проектировать primary, secondary и diagnostic цели;
- проверять одно срабатывание события, источник, UTM/yclid и ценность;
- работать с ecommerce, звонками, заявками и CRM-статусами;
- разделять платформенную конверсию и бизнес-источник истины;
- рассчитывать CTR, CR, CPA, ROAS и прибыль;
- находить запросы с расходом без результата;
- не превращать эвристику в автоматическую минусацию.

Результат: preflight измерений и таблица поисковых запросов с обоснованными
рекомендациями для ручной проверки.

Инструкция:
[`measurement-and-optimization.md`](../skills/yandex-direct/references/measurement-and-optimization.md).

Аудит поисковых запросов:

```bash
python skills/yandex-direct/scripts/yandex_direct_toolkit.py \
  audit-search-terms examples/search-terms.example.csv \
  --output outputs/search-terms-audit.csv \
  --target-cpa 3500
```

## 9. A/B-тестирование

Когда применять: сравнение рекламных углов, заголовков, посадочных, CTA или другой
одной значимой переменной.

Что делает:

- формулирует проверяемую гипотезу;
- фиксирует контроль и до четырех вариантов;
- задает primary metric, guardrails, MDE, alpha, power и окно чтения;
- считает двухвыборочный z-тест для конверсий/кликов;
- отдельно показывает статистическую определенность и практический эффект;
- оставляет решение `UNDECIDED`, если нет заранее согласованного владельца и правила.

Команда readout:

```bash
python skills/yandex-direct/scripts/yandex_direct_toolkit.py \
  experiment-readout \
  --control-success 30 --control-n 1000 \
  --variant-success 42 --variant-n 1000 \
  --min-relative-lift 0.10
```

## 10. Безопасная работа с Wordstat и Direct API

Когда применять: сбор живых данных или публикация подготовленных объектов.

Предохранители:

- Wordstat и Direct по умолчанию работают в режиме preview;
- платные Wordstat-вызовы требуют `--execute --confirm WORDSTAT:N`;
- live-мутация требует точную строку вида `LIVE:ads:add`;
- sandbox и production разделены;
- OAuth-токен Direct не смешивается с API-ключом Search API;
- токены читаются только из переменных окружения;
- payload показывается до отправки и получает SHA-256;
- HTTP 200 не считается полным успехом без проверки поэлементных ошибок;
- созданные объекты перечитываются по ID;
- запуск, бюджет, стратегия, удаление и минус-фразы требуют отдельных решений.

Создание `ResponsiveAd` payload:

```bash
python skills/yandex-direct/scripts/yandex_direct_toolkit.py \
  build-responsive-payload examples/campaign-package.example.json \
  --output outputs/ads.add.json
```

Предпросмотр live-запроса:

```bash
python skills/yandex-direct/scripts/yandex_direct_toolkit.py \
  direct-request ads outputs/ads.add.json \
  --environment production
```

Инструкция:
[`api-and-safety.md`](../skills/yandex-direct/references/api-and-safety.md).

## Доступные команды CLI

| Команда | Назначение |
|---|---|
| `validate-package` | Проверить структуру, лимиты, утверждения, URL и message match |
| `build-responsive-payload` | Собрать `ads.add` payload с `ResponsiveAd` |
| `normalize-semantics` | Очистить, дедуплицировать и предварительно разметить семантику |
| `wordstat-top` | Выполнить или предварительно показать запросы Wordstat v2 |
| `build-utm` | Добавить стабильные UTM и динамические параметры Директа |
| `audit-search-terms` | Рассчитать экономику фактических поисковых запросов |
| `experiment-readout` | Рассчитать эффект и неопределенность A/B-теста |
| `direct-request` | Безопасно показать или выполнить один Direct API-запрос |

Полный список:

```bash
python skills/yandex-direct/scripts/yandex_direct_toolkit.py --help
```

## Примеры запросов к навыку

```text
Используй $yandex-direct. Собери семантику для услуг промышленного электромонтажа
по Москве. Нужны B2B-запросы, минус-фразы и кластеры без публикации.
```

```text
Используй $yandex-direct. Проверь выгрузку поисковых запросов, найди упущенный
спрос и подготовь предложения по минусации с учетом CPA и качества лидов.
```

```text
Используй $yandex-direct. Создай 7 заголовков и 3 текста ResponsiveAd для каждого
кластера. Используй только утверждения, подтвержденные указанной посадочной.
```

```text
Используй $yandex-direct в режиме audit. Ничего не меняй в аккаунте. Проверь
структуру, автотаргетинг, объявления, запросы, Метрику и экономику кампаний.
```

## Что инструмент не обещает

- гарантированные продажи, CPA или прибыль;
- автоматическую победу над любым конкурентом;
- прохождение модерации без необходимых документов;
- корректную оптимизацию при сломанной Метрике;
- автоматическое применение минус-фраз без проверки;
- live-изменения без отдельного подтверждения пользователя.

Инструмент системно улучшает контролируемые факторы: качество семантики,
релевантность, доказуемость оффера, структуру кампаний, посадочную, измерения и
дисциплину экспериментов.
